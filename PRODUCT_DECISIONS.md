# Product decisions — synthetic Scout Copilot

- **Problem:** a scout needs to inspect defensive-transition and build-up involvement alongside ordinary attacking counts, without mistaking a small sample for player ability.
- **Hypothesis:** a structured request that returns linked supporting and opposing events could reduce time to a defensible first observation. This remains untested with users.
- **Boundary:** the separate self-authored fixture has three players and one fictional match. Phase labels are authored annotations. Counts are event totals, not ratings, calibrated xG, possession value or exposure-adjusted comparisons. The UI displays a native-coordinate pitch, not tracking or certified direction.
- **Tradeoff:** the current interpreter is a conservative rules baseline. A provider-independent structured-query callback is validated against the supported rules, and explanations are deterministic templates built from source events. Unsupported constraints, comparisons and abilities abstain. This deliberately limits natural-language coverage; it is not a live AI system and cannot demonstrate AI uplift. No provider credentials were available and no model was called.
- **Baseline and evidence:** the 36 development tasks compare this fallback with a literal full-request substring search proxy for the existing Discover interface. The proxy does not model a human reformulating a search. See `docs/benchmarks/scout-copilot/` for exact outcomes, failures, grading limits and reproducible commands. Neither proxy results nor synthetic sessions establish user value.
- **Failed approaches:** the initial scouting dataset had only passes and shots, so it could not support transition claims; a separate fictional fixture was authored rather than relabeling existing records. A mobile overflow in the earlier discovery table was caught and fixed during browser testing. A full benchmark case still safely abstains but has a mismatched intent label; it is retained in raw outcomes.
- **Metric and next experiment:** Time to First Defensible Insight starts at Discovery and ends when a user confirms completion after evidence. The local funnel records only opt-in stage names and elapsed time; confirmation is not independent proof of defensibility. With consent, compare a real model-backed version against normal search on held-out tasks, review the evidence and unsupported claims independently, and measure time, completion, latency and actual cost. Do not make engagement or AI improvement claims from synthetic sessions.
